# AI Usage Policy

AI-generated code, documentation and issues are generally allowed in this project. Even entire
features can be generated completely by AI, as long as the code is good and reviewed.

## Terms

- **Review and understand generated code**

    Generated code MUST be reviewed, understood and, if necessary, manually modified before
    contributing it. It MUST be possible to maintain the code even without AI support.

- **Mark in pull requests**

    Commits don't need an assisted-by or similar marker, but in the pull request it is required
    to mark in the form and with a label that the PR contains generated code, together with a short
    note about what was generated in the PR.

## Restrictions

- **No pull requests, reviews or commit messages by AI agents**

    Pull requests created by AI agents will be rejected. They MUST come from a human. The texts of
    pull requests and commit messages MUST also be written by hand. This is necessary to show that
    you have an idea of what you want to contribute.

    Reviews of pull requests MUST also be done by a human. When code is already generated by AI,
    it is useless to also let AI, which may use the same model in the background, review the
    contributed code.

- **No walls of generated text in the documentation and issues**

    Documentation and issue texts are allowed to be generated, but AI can easily generate more text
    than anyone wants to read. They should be kept to a reasonable length as good as possible.

- **AI may not be used for issues marked as "good first issue"**

    These issues are intended for new contributors to learn the codebase and are thus wasted if
    AI solves them.
